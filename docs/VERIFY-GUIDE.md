# 怎么验证（给你看的，不需要懂代码）

> 2026-10-31 改版。这一版起：**同一套脚本在真机和两种模拟器上都能跑**，不用为每个设备改坐标。
> 脚本自己会把坐标标定好。

---

## 0. 三条铁律（先看这个，能省掉 80% 的「点了没反应」）

1. **设备与分辨率无关的坐标一律用 vp**，脚本按实测密度换算成设备像素。
   你自己手动点的时候，也请按 vp 换算，不要直接抄上一轮的屏幕像素。
2. **画布顶边在屏幕上的偏移，每个设备都不一样**，脚本用 `tools\probe_canvas.py` 从截图里量出来。
   任务里给的偏移数字经常过期 —— 以脚本量出来的为准。
3. **自动化脚本必须加延时**。画布重绘有延迟，连点两次可能只有第一次生效。
   `tools\verify.ps1` 里的 `Tap` 默认已经带 500 ms 延时。

## 2. 模拟器上怎么用（`tools\emu.ps1`）

DevEco 自带 HarmonyOS 模拟器，本机装的是 **Mate X7**（折叠屏，API 26.0.0，2210×2416 @ density 500）。

| 动作 | 命令 |
|---|---|
| 启动 | `emu.ps1 -Action start` |
| 关闭 | `emu.ps1 -Action stop` |
| 看状态 | `emu.ps1 -Action status` |
| 折起来 / 展开 | `emu.ps1 -Action fold -Fold closed`（或 `open`） |
| 截图 | `emu.ps1 -Action shot -Name myshot` |
| 装包 | `emu.ps1 -Action install` |
| 启动应用（并清空日志） | `emu.ps1 -Action launch` |

**三个坑（脚本注释里也写了）：**

1. **必须用 `Start-Process` 脱离启动**。用 `Start-Job` 或前台跑，工具调用一结束模拟器会被一起清理掉。
2. **第一次要 `-license accept`**，否则起不来。
3. 引导 60~90 秒，镜像校验 `system.img` 就要 40 秒。`hdc list targets` 里出现 `127.0.0.1:5555` 才算好。

另一台模拟器 **Mate 90 Pro** 在 `127.0.0.1:5557`（1280×2832 @ density 3.5）。

## 3. 坐标换算：自己手动点的时候怎么看

脚本内部是这么算的，你手动点时可以照抄：

```
屏幕 X = vp 坐标 × 密度
屏幕 Y = 画布顶偏移 + (vp 坐标 × 密度)
```

| 设备 | 密度（px per vp） | 画布顶在屏幕 y |
|---|---|---|
| Pura X Max 真机 | 2.75 | 用 `probe_canvas.py` 量，**不要抄旧数字** |
| Mate X7 模拟器 | 3.125 | 同上 |
| Mate 90 Pro 模拟器 | 3.5 | 同上 |

量画布顶偏移：

```powershell
python D:\software\harmony\projects\minesweeper\tools\probe_canvas.py <截图路径> <棋盘原点x> <棋盘原点y> <格边px>
# 输出 CANVAS_Y=<数字>
```

棋盘原点和格边从应用的日志里读：

```powershell
& 'D:\software\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe' -t <设备> shell hilog -x | Select-String '布局'
# [GameController] 布局 画布=WxHpx 密度换算=… 格边=Spx 棋盘原点=(X,Y)
```

> `probe_canvas.py` 有个坑：采样点必须取**格边中心**（`bx + tile/2`）。
> 取 `bx + 4` 会正好落在砖块左缘的暗边上，偏移算成 225（实际 121），后面的点击全偏。

## 4. 脚本管不到的事，需要你手动做

### 4.1 双指捏合缩放（必须人工）

真机与模拟器的手势注入都**没法模拟两根手指**，所以这一项只能你来：

1. 打开扫雷，**两根手指在棋盘上捏一下**（放大或缩小都行）
2. 告诉我一声，我去日志里找 `[Touch] 捏合 档位n=…` 这一行
   —— 有这行就说明捏合被正确识别了，档位数字会跟着变
3. 顺便确认：捏完之后**单指能不能把棋盘拖回来**（高级局在窄屏上是允许超宽的）

### 4.2 折叠屏换屏

1. 在游戏进行中**把手机折起来**（内屏 → 外屏），再展开回来
2. 看两点：棋盘还在不在、计时器数字有没有乱
3. 日志里应该有 `[GameController] 布局` 这一行，把折叠前后的两行都发我

模拟器上可以用 `emu.ps1 -Action fold -Fold closed` / `open` 代替。

### 4.3 音效（这一轮修完还没人听过）

上一轮修了「所有音效都不响」的 bug（`AVPlayer` 的 `fdSrc` 是异步状态机，设完立刻 `prepare()` 会抢跑）。
请在真机上确认这四个事件**有声音**：

| 操作 | 该响的音效 |
|---|---|
| 菜单「游戏 → 新建」 | 开局音 |
| 点开一个格子 | 开格音 |
| 长按插旗 | 旗子音 |
| 踩雷 | 爆炸三段连播 |

### 4.4 窄屏 30 列局的观感

最近加了条规则：**装得下但格子边长小于 48 像素时，宁可让棋盘横向超出屏幕（可以拖动），也不要给一个点不准的棋盘**。

在 90 Pro 上已复测：高级局从 n=1（格边 36）抬到 **n=2（格边 72）**，棋盘宽 1080→2160 px，
在 1280 宽的屏上**横向出屏 440 px**（这是有意的）。

请在 90 Pro 或 Pura X Max **外屏**上再确认三件事：

1. 格子**点得准**（不用使劲戳）
2. 你**接受**「要看全盘得拖一下」这个代价
3. **棋盘顶部有没有被菜单栏压住**（看不见也点不着）——
   这条曾经是个真问题（静态审计 `docs\LEAD-CHANGE-AUDIT.md` 的 L1），**13:51 已经修了**
   （抬档加了前提 + 纵向溢出改顶对齐），但**修完还没在设备上复测过**，所以特别需要你确认一下。

### 4.7 「颜色(C)」外观对话框：绿色棋盘 + 花园玩法

这一轮新加的功能（原版 Win7 的 **"Change Appearance"（F7）**）。
实现记录与版式见 `docs\APPEARANCE-DIALOG.md`。

#### (1) 打开与选择

1. 点「游戏(G)」→ 下拉里应该有**「颜色(C)」**，位置在**「最佳成绩」之后、「退出」之前**（倒数第二项）
2. 点它 → 弹出「颜色」对话框，里面应该有：
   - 上面的**「游戏样式」**分组框：两枚缩略图 —— **扫雷** / **花园**
   - 下面的**「棋盘」**分组框：两枚缩略图 —— **银蓝** / **绿色**
   - 一个**置灰的**「随机选择游戏样式和棋盘」复选框（**原版就是灰的，点不动是正常的**）
   - 底部「确定(O)」「取消(C)」
3. 点「绿色」缩略图 → 选中框应该移到绿色那一枚，说明文字变成蓝底白字

> 模拟器实测已通过，截图 `X7_91_final_dialog.jpeg` / `X7_92_final_green_selected.jpeg`。

#### (2) 「确定」才生效，「取消」不生效

1. 点「确定(O)」→ 对话框关闭，**棋盘变绿**
2. 重新打开 → 点「花园」→ 点**「取消(C)」** → 棋盘应该**保持原来的绿色不变**
   （原版帮助原文 "Make your choices, and then click OK"，所以取消不生效）

> 模拟器实测已通过，截图 `X7_93_final_green_board.jpeg`；绿色像素数 43 589 → 2 304 302。

#### (3) 花园玩法

1. 打开对话框 → 点「花园」缩略图 → 点「确定」
2. 开一局，看**剩余雷数旁边的图标**是不是变成了**白雏菊**（不再是尖刺地雷）
3. **踩雷**时应该是**花朵**炸开，不是地雷；判负音效按**剩余雷数**分三段
   （≤10 短 / ≤40 中 / 更多长）

> 模拟器实测只验到**图标与帧的位置**（`X7_90_flower_game.jpeg`）。
> **判负瞬间的完整开花序列没验过**，需要你走一局踩雷看看。

#### (4) 重启后还记得吗（**已实测通过**）

1. 选「绿色」→ 点「确定」
2. **完全杀掉应用**（不是切后台）
3. 重新打开 → 棋盘应该**还是绿色的**（原版就是持久化的）

> 外观设置存在 preferences 里（`boardStyle` / `gameStyle` 两个键）。
> **已实测**（Mate X7 内屏）：选绿色 → 确定 → **完全杀掉应用** → 重开 → 棋盘**还是绿色的**
> 截图 `docs\verify\M6_after_restart.jpeg`；日志 `[GameStats] 外观已保存 board=1 game=0`。
> （原版就是这个行为，持久化。）

## 9. 另外：两条已知的「故意不同」

   这个版本是「第一下必定开出一片空地」。这是当初定方案时就拍板的选择，不是 bug。

   （依据见 `docs\STATUS-STRIP-VERDICT.md` 结论 A）。项目已有 F2 与菜单「新建」两条正路。
