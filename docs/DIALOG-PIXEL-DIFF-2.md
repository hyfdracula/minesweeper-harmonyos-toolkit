- 标题栏：参考图是**高饱和粉紫 Aero 渐变**（`rgb(248,222,247)` → `rgb(239,213,238)`），

数字键盘仍是**外挂**在对话框右侧（框到 795、键盘从 824 起，中间 29 px 缝），
**但整组 800 px 在 1280 宽的屏上放得下，左右各余 240 px**。

### 4.3 三个输入框能不能用数字键盘敲进去

可以，**三个框都能敲**（`docs/verify/DLG2_custom_values_strip.png` 是四组取值对照条）：

| 步骤 | 高度 | 宽度 | 雷数 | 说明 |
|---|---|---|---|---|
| 点「高度」框 → 退格 x2 | 0 | 0 | 65 | 清空后回显 **0**（不是空白） |
| 接着按 9、9 | **9** | 0 | 65 | 「99」越界（上限 24），**第二个 9 被拒绝**，留在 9 |
| 退格 → 按 3、3 | **3** | 0 | 65 | 「33」越界，同样被拒绝 |
| 退格 → 按 2、4 | **24** | 0 | 65 | 24 正好是上限，接受 |

另外单独验证过：
- 点「宽度」输入框 → 焦点切过去 → 按 2、3 → 宽度变成 2 位（OK，`DLG2_custom_width.jpeg`）
- 点「雷数」输入框 → 焦点切过去 → 按 8、8 → 雷数变成 2 位（OK，`DLG2_custom_mines.jpeg`）

→ **数字键盘对三个框都生效，点哪个框就往哪个框里敲。**

### 4.4 超出范围的回显：**是「拒绝」不是「夹取」，和 lead 的预期有出入**

- **按键阶段**：越界的按键被**拒绝**（不写入），字段保持上一位合法值。
  输 `99` 得到 `9`，输 `33` 得到 `3`，**不会**被夹到上限 24。
- **清空阶段**：退格删空后字段显示 **`0`**，不是空白。
  高度 0 低于下限 9、宽度 0 低于下限 9 —— 但这只是个**回显**，不是最终生效值。
- **确定阶段**：这时才真正夹取。把宽度留成 0 再按「确定(O)」，
  日志打出新盘面 `适配档n=2 当前档n=2 unit=4 格边=72px 棋盘原点=(316,408) HUD=0 状态条上沿=2136px`
  → 反推盘面是 **24 行 x 9 列**（316 + 9x72 = 964，1280-964 = 316，左右对称；408 + 24x72 = 2136 与状态条上沿吻合），
  即 **宽度 0 被夹成了下限 9**，高度 24 被保留。

→ 给 lead 的一句话：**回显有，但夹取发生在「确定」而不是「按键」**。
按键阶段是「拒绝越界键」。如果 lead 的要求是「越界键直接夹到边界」（输 99 直接变 24），
那这是**要改**的；如果「按键拒绝 + 确定时夹取」是想要的行为，那就是现状、只需在 SPEC 里写清楚。
