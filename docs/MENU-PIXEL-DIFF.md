# 菜单栏像素级复检（MENU-PIXEL-DIFF）

复检对象：HarmonyOS 扫雷的**菜单栏**（游戏(G) / 帮助(H) + 下拉面板 + 展开高亮态）
复检设备：**127.0.0.1:5555（Mate X7 模拟器，画布 2210×2208，密度 3.125，格边 180px）**
对照参考：Win7 原版扫雷整窗截图
日期：2026-11-01

---

## 0. 一句话结论

**菜单栏本身没有找到确定性偏差，本轮没有改代码。**

- 菜单栏**底色渐变与分隔线**与 Win7 参考图**逐像素一致率 100%**（容差 12，两个设备都是）；
- 栏高、基线、两个标题的横向位置与参考图的偏差 **≤ 0.6 参考像素**（0.6/96 英寸）；
- 文字区一致率只有 66%~69%，差的是**字形本身**（设备用 HarmonyOS 默认无衬线体，
  原版是 Win7 的 Segoe UI 12px），不是排版偏差；
- 5555 与 5557 两台设备（画布 2210×2208 vs 1280×2598，密度 3.125 vs 3.5）
  的菜单栏几何**互相差 ≤ 0.3 参考像素**，说明排布与密度无关 ✓。

> 另：lead 指名要改的 `entry/src/main/ets/common/MenuBar.ets` **在 app 仓里不存在**；
> 菜单栏的代码在 `entry/src/main/ets/common/WinMenu.ets`（`WinMenuPainter`）。
> 本轮因为没有需要改的地方，没有触碰该文件。详见 §7。

### 1.2 坐标系与换算

参考图是 100% DPI 的整窗截图，1 参考像素 = 1 逻辑像素（vp）。

```
画布顶（屏幕 y）        : 用菜单栏渐变的第一行 #fefeff 定位（纯白系统区之后的第一行）
设备像素 → 参考像素     : ÷ (密度 × 14/12)
                          14 = 本实现字号(vp)，12 = 参考图字号(px)，比值 1.1667
参考像素 → 窗口坐标     : + 8（内容左边；x=7 是 1px 窗框）
```

| 设备 | 画布顶(屏幕) | 密度 | 1 参考像素 = | 菜单栏栏体 |
|---|---|---|---|---|
| 5555 | 122 | 3.125 | 3.6458 设备px | 66 px = 21.12 vp = 18.10 参考px |
| 5557 | 135 | 3.5 | 4.0833 设备px | 74 px = 21.14 vp = 18.12 参考px |

> 注：`tools/probe_canvas.py` 报的画布顶（5557 = 139）比真实值大 4px ——
> 那是因为它取「第一块砖的**砖色**上沿」，砖块顶部 4px 是立体斜面不算砖色。
> 差 4px 不影响点格子（格边 108~180px），但做像素对齐时要用本节的 135/122。

## 6. 复检过程中发现的两处「事实性出入」

只报告，不改（涉及的文件不在本轮写范围内）：

1. `WinMenu.ets` 文件头：「gaming.jpg / initializing.jpg 三张在菜单栏区域逐像素一致」——

   gaming 的背景随桌面底色变化，文字位置一致」。
2. `WinMenu.ets` 文件头：「本工程菜单栏用的字号（vp）——主线程 GameController.drawMenu 里写死的是 14vp」——
   实测 5555/5557 两台设备上字号换算正确（14vp = 12 参考px × 14/12），栏体 21 vp 也一致，无问题；
   但文件头的「参考图实测」段没有写明「14/12 的放大是有意的」（触屏可读性），
   建议补一句，免得后来人误当成 bug 去「修」成 12vp。
