# 真机验收清单（Pura X Max）

> **给谁看**：手上只有一台华为 Pura X Max 典藏版、不写代码的你。
>
> **设备**：内屏 2584 × 1824（横屏），外屏 1323 × 1936，密度 2.75。
>
> **怎么用**：从第 1 节往下做。每一步都写了「算什么通过」「算什么失败」，
> 失败了把该发的东西发回来就行，**不用你判断原因**。
>
> **全程大约 40 分钟**。建议**每做完一步截一张图**，图名就写步骤号（比如 `3-1.png`）。

---

## 0. 先看这三条（不然你会以为坏了）

### 0.1 手机上没有「右键」，插旗是**长按**

Win7 电脑版是「右键插旗」。手机是触摸屏，**没有右键**，
所以本移植把右键改成**长按**（按住不放约半秒再松开）。

帮助对话框里那句「左键翻开格子；右键插旗，再右键变问号」是**原版 Win7 的说明文字**，
照搬过来的，手机上对应的是「单击开格；长按插旗，再长按变问号」。
**这句话本身不算 bug**，但别照着它找右键。

### 0.2 捏合缩放的档位**不写日志**

双指捏合改缩放时，程序**不会**打一行「捏合 档位n=」的日志（这个功能没做）。
想知道捏到了第几档，看**第 11 节**的办法（靠折叠一次把日志逼出来）。

### 0.3 声音**从来没验证过**

音效的代码写了，但**没有人听过它到底响不响**（2026-11-01 之前一直没实测）。
所以：如果你觉得没声音，**不算这一步失败**，但请在最后一节里写一句「我没听到声音」。

## 1. 装 HAP（只做一次，以后不用再做）

### 步骤 1-1　手机上打开开发者选项

**做什么**：手机 → **设置 → 关于手机** → 找到 **版本号** → **连点 7 下** → 输入锁屏密码。

- **算通过**：提示「您已处于开发者模式」，或返回上一层后多出「开发者选项」这一项。
- **算失败**：连点 7 下没有反应、或者提示次数太多要等 24 小时。
- **失败时发回来**：说一声「版本号点不动」就行，不用截图。

### 步骤 1-2　手机上打开 USB 调试

**做什么**：手机 → **设置 → 系统和更新 → 开发者选项**（有的版本在「设置 → 关于手机 → 开发者选项」）→ 打开 **「USB 调试」**。

- **算通过**：开关变成打开状态（通常是深色）。
- **算失败**：找不到「开发者选项」这一项 → 多半是 1-1 没做成，回去重做。
- **失败时发回来**：把你看到的开发者选项第一屏截图发回来。

### 步骤 1-3　插上数据线，手机上选「传输文件」

**做什么**：用**能传数据**的 USB 线连电脑（有些线只能充电）。手机下拉通知栏 → 点「正在通过 USB 充电」→ 选 **传输文件（MTP）**。

- **算通过**：手机下拉栏里出现「正在通过 USB 传输文件」。
- **算失败**：手机一直显示「仅充电」→ 换一根线。
- **失败时发回来**：说一声「换了线还是仅充电」。

### 步骤 1-4　手机上允许这台电脑调试

**做什么**：插上线的几秒内，手机会弹一个框「是否允许 USB 调试？」→ 勾上 **「一律允许使用这台计算机进行调试」** → 点 **允许**。

- **算通过**：弹窗消失，手机不再提示。
- **算失败**：没有弹窗 → 把 USB 线拔下来重插一次；还是不弹 → 往下走 1-5，看电脑能不能认到。
- **失败时发回来**：说一声「没弹授权框」。

### 步骤 1-5　电脑上确认认到了手机

**做什么**：在电脑上打开 **PowerShell**（开始菜单搜 `powershell`），把下面三行**原样粘进去**、回车：

```powershell
$hdc = 'D:\software\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe'
& $hdc list targets
$d = '6HR0226409003317'   # Pura X Max 的序列号
```

- **算通过**：屏幕上除了 `127.0.0.1:5555`、`127.0.0.1:5557` 这两行（那是两台模拟器，不用管），
  **还多出 `6HR0226409003317` 这一行**。
- **算失败**：只看到那两行模拟器，没有 `6HR0226409003317`。
- **失败时发回来**：把 `hdc list targets` 的**全部输出**截图或复制过来。

### 步骤 1-6　把应用装到手机上

**做什么**：在同一个 PowerShell 窗口里粘这两行、回车：

```powershell
& $hdc -t $d install -r 'C:\Users\19161\saolei\entry\build\default\outputs\default\entry-default-signed.hap'
```

- **算通过**：屏幕上出现 `install bundle successfully` 之类带 `success` 的字样。
- **算失败**：出现 `failed` / `error`。**常见两个原因**：
  （1）应用没签名（`.p12` / `.cer` 没生成）；
  （2）手机上的开发者选项没开「监视应用安装」。
- **失败时发回来**：**把这一段的完整输出复制过来**（一个字符都别删），这一条最好定位。

### 步骤 1-7　启动应用

**做什么**：同一窗口里粘这行、回车：

```powershell
& $hdc -t $d shell aa start -a EntryAbility -b com.example.saolei
```

然后**看手机屏幕**。

- **算通过**：手机桌面（或别的界面）上出现扫雷画面：左上角是「游戏(G) 帮助(H)」菜单栏，
  中间是方格棋盘，底部状态条左边是**时钟**、右边是**雷数**。
- **算失败**：应用没起来（画面没变），或者起来了马上闪回桌面。
- **失败时发回来**：手机截图 + 第 11 节的日志。

> 桌面图标的名字是 **`saolei`**（全小写），也可以在手机上直接找这个图标点开。

## 2. 开一局

### 步骤 2-1　点第一下，看有没有开出一片

**做什么**：用手指**点一下**棋盘中间任意一格，点完等 1 秒。

- **算通过**：那一片格子翻开了（可能是一整片空白，也可能带数字），
  底部状态条左边开始**跳秒**（计时在走）。
- **算失败**：格子没翻、或者整个应用没反应。
- **失败时发回来**：手机截图。

### 步骤 2-2　看计时是不是在走

**做什么**：盯着状态条左边的计时数字，看 5 秒。

- **算通过**：数字在往上跳。
- **算失败**：数字不动（一直是 0）。
- **失败时发回来**：手机截图。

### 步骤 2-3　长按插一面旗

**做什么**：在一个**还没翻开**的格子上**按住不放约半秒**，然后松开。

- **算通过**：那一格变成**红旗**，同时底部状态条右边的**雷数减 1**。
- **算失败**：格子直接翻开了（说明当成单击处理了），或者雷数没减。
- **失败时发回来**：手机截图（要能看到那一格和右边的雷数）。

> 再长按一次，那面旗会变成**问号**（如果「标记(?)」是开的）；再长按第三次，变回**没标记**。

## 3. 折叠开合（你最在意的部分）

### 步骤 3-1　先展开，用内屏

**做什么**：把手机**完全展开**成「平板」姿态（左右两块屏幕摊平），等 2 秒。

- **算通过**：画面变成**横屏**，棋盘完整地摆在中间，左右没有黑边或者被裁掉；
  菜单栏「游戏(G) 帮助(H)」在左上角，状态条在底部，**两个都看得到**。
- **算失败**：画面没变、变成竖屏、或者棋盘被裁掉一块。
- **失败时发回来**：手机截图（整屏）。

### 步骤 3-2　折起来，用外屏

**做什么**：把手机**折起来**（合上），等 2 秒。

- **算通过**：画面变成**竖屏**的小屏，菜单栏、棋盘、状态条**都在屏内**，
  没有任何一块被切掉；棋盘格子依然**方方正正**（不是被拉扁的）。
- **算失败**：画面黑掉、卡在展开态、或者有内容被裁掉。
- **失败时发回来**：手机截图（整屏）。

### 步骤 3-3　再展开回去

**做什么**：重新展开成平板姿态，等 2 秒。

- **算通过**：回到步骤 3-1 的横屏画面，棋盘还在，格子没变形。
- **算失败**：黑屏、或者棋盘位置乱掉。
- **失败时发回来**：手机截图。

### 步骤 3-4　在外屏上能不能点得准

**做什么**：折起来（外屏），在棋盘上**点一下**某个格子。

- **算通过**：**你点的那个格子**翻开了（周围一圈也可能一起翻开）。
- **算失败**：翻开的是**旁边的格子**（点歪了），或者点了没反应。
- **失败时发回来**：手机截图（要能看出点的是哪一格）。

## 4. 折叠过程中，局面保不保得住

这一节是整个验收里**最重要**的一节：折一下、展开一下，**雷位、旗、计时、翻开的格子**都得还在。

### 步骤 4-1　先造一个「有内容」的局面

**做什么**：展开成内屏，然后做三件事：
1. 点开中间一格（开一片）
2. 在两个没翻开的格子上**长按**插旗
3. 等计时跑到 **5 秒以上**

- **算通过**：棋盘上有翻开的格子、有红旗、计时在 5 秒以上。
- **算失败**：旗插不上、或者翻不开。
- **失败时发回来**：手机截图。

### 步骤 4-2　折起来（外屏），看局面还在不在

**做什么**：保持上面那个局面，**把手机折起来**，等 2 秒。

- **算通过**（四条都要满足）：
  1. 翻开的格子**还是翻开的**
  2. 那两面红旗**还在**（还是红旗，不是问号，也不是没了）
  3. 计时数字**继续在走**（不是从 0 开始，也不是停住）
  4. 雷数**还是原来的数**（没有回到 10）
- **算失败**：上面四条里任何一条不满足（比如旗没了、计时归零、雷数重置）。
- **失败时发回来**：**折起来那一屏的截图** + **展开后的截图**（两张都要），
  再加第 11 节的日志。

### 步骤 4-3　再展开，看局面还在不在

**做什么**：重新展开成内屏，等 2 秒。

- **算通过**：跟 4-2 那四条一样，全都保持住。
- **算失败**：同上。
- **失败时发回来**：展开后这一屏的截图 + 第 11 节的日志。

### 步骤 4-4　折合的**半路**也要看一眼（悬停姿态）

**做什么**：把手机折到**一半**停住（像「帐篷」那样斜着），等 2 秒，看一眼，再合上。

- **算通过**：画面正常显示（**不要求好看**，只要不黑屏、不崩溃就行）。
- **算失败**：黑屏、卡死、或者闪退。
- **失败时发回来**：手机截图 + 日志。

## 5. 双指捏合缩放

### 步骤 5-1　先记住捏合前的样子

**做什么**：展开成内屏，**截图**（这张叫 `before.png`）。

- **算通过**：拿到一张清楚的棋盘截图。
- **失败时发回来**：不用发。

### 步骤 5-2　张开手指放大

**做什么**：**两只手指同时按在棋盘上**，然后**同时往外张开**（像放大照片），
一直张开到最大，等 1 秒。

- **算通过**：格子**明显变大**了，而且格子**还是方的**（没有被拉变形）。
- **算失败**：没变化、或者格子变形、或者画面卡住。
- **失败时发回来**：`before.png` 和捏合后的截图（两张都要）。

### 步骤 5-3　捏拢缩小

**做什么**：接着**两只手指同时往中间捏**（像缩小照片），捏到最小，等 1 秒。

- **算通过**：格子**明显变小**了，整盘棋基本能看全。
- **算失败**：没变化、或者变形。
- **失败时发回来**：截图。

### 步骤 5-4　捏合后能不能拖动看边上的格子

**做什么**：捏到小（整盘看不全）之后，**一根手指按住棋盘拖动**，把棋盘往左拖、再往右拖。

- **算通过**：棋盘**跟着手指动**，能看到边上那些原本在屏外的格子。
- **算失败**：棋盘纹丝不动、或者一拖就飞出去找不回来。
- **失败时发回来**：截图。

> **为什么单独测这个**：30 列的局在窄屏上装不下，程序会**故意**让棋盘超出屏幕边，
> 靠拖动来看 —— 这是**设计如此**，不是溢出 bug。
> 详见 `docs\SPEC.md` §7.3。

### 步骤 5-5　捏到第几档（可选，看第 11 节）

想知道具体捏到了第几档，看**第 11 节**。

## 6. 长按插旗（Win7 的「右键插旗」在手机上的样子）

### 步骤 6-1　第一长按 → 红旗

**做什么**：在一个没翻开的格子上长按约半秒后松开。

- **算通过**：变成**红旗**，雷数 **−1**。
- **算失败**：格子翻开了（说明被当成单击）。
- **失败时发回来**：截图。

### 步骤 6-2　第二长按 → 问号

**做什么**：在**同一格**上再长按一次。

- **算通过**：红旗变成**问号**，雷数**不变**（还是 −1 之后的那个数）。
- **算失败**：变成红旗（没循环）、或者直接翻开。
- **失败时发回来**：截图。

> 如果「游戏(G) → 标记(?)」是**关**的（菜单里这一项没打勾），那么只有
> **红旗 ↔ 没标记**两态，**不会有问号** —— 这是原版 Win7 就有的开关。

### 步骤 6-3　第三长按 → 回到没标记

**做什么**：再长按一次。

- **算通过**：问号（或旗）变回**没标记**的灰格子，雷数**加回来 1**。
- **算失败**：没变。
- **失败时发回来**：截图。

### 步骤 6-4　插了旗的格子点不开

**做什么**：点一下刚才插了旗的那一格。

- **算通过**：那格**没翻开**（还是旗）。
- **算失败**：旗被翻开、或者整片被翻开。
- **失败时发回来**：截图。

## 7. 菜单栏每一项

**怎么打开菜单**：点屏幕**左上角**的「**游戏(G)**」或「**帮助(H)**」，会弹出一个下拉菜单；
再点一次菜单栏同一个字，菜单收起。

> 下拉菜单里**横线**是分隔条，不能点，这是正常的。

### 步骤 7-1　游戏(G) → 新建 (F2)

**做什么**：游戏菜单 → 点 **「新建」**。

- **算通过**：棋盘**全部清空**（回到没开过的样子），计时**归零**重新开始。
- **算失败**：棋盘没清、或者计时没归零。
- **失败时发回来**：截图。

### 步骤 7-2　游戏(G) → 初级 / 中级 / 高级

**做什么**：依次点 **初级**、**中级**、**高级**，每次都看清棋盘的变化。

- **算通过**：
  - 初级 = **9 列 × 9 行**，**10 个雷**
  - 中级 = **16 × 16**，**40 个雷**
  - 高级 = **30 列 × 16 行**，**99 个雷**
  状态条右边的雷数应该分别是 10 / 40 / 99。
- **算失败**：行列数或雷数跟上面写的对不上；或者选了以后**菜单还留在屏幕上不消失**。
- **失败时发回来**：三张截图（每种难度一张），要能看到整盘和状态条。

### 步骤 7-3　游戏(G) → 自定义

**做什么**：游戏菜单 → 点 **「自定义」**。

- **算通过**：弹出一个对话框，**左边三个输入框**（高度 / 宽度 / 雷数），
  **右边一整块数字键盘**。
- **算失败**：没弹框、或者弹出来是空白。
- **失败时发回来**：截图。

### 步骤 7-4　在自定义框里开一局 24×30（顺便验键盘）

**做什么**：在「高度」框上点一下（它会亮起蓝框），用右边的数字键按 **2**、**4**，
再点「宽度」框，按 **3**、**0**；雷数不动（保持 10）；最后点 **「确定(O)」**。

- **算通过**：
  1. 高度框里变成 **24**，宽度框里变成 **30**
  2. 点确定以后，棋盘变成 **30 列 × 24 行**
  3. 底部状态条**完整可见**（时钟 + 计时 + 雷数 + 雷图标都在屏内）
- **算失败**：框里的数字不对、或者确定以后状态条有东西跑出屏幕。
- **失败时发回来**：填好数字那一张 + 开局后那一张（两张都要）。

> 这一局棋盘是**故意比屏幕宽**的（30 列在窄屏上装不下），
> 靠**单指拖动**看边上的格子，这是**设计如此**。

### 步骤 7-5　游戏(G) → 标记(?)

**做什么**：游戏菜单 → 点 **「标记(?)」**，看菜单项旁边的勾；再点一次，看勾消失。

- **算通过**：点一下这个项的**勾出现/消失**，而且**菜单整个消失**（回到棋盘）。
- **算失败**：**菜单整块留在屏幕上**（这是历史上真出过的 bug），或者勾不变化。
- **失败时发回来**：截图（要能看到残留的菜单）。

### 步骤 7-6　游戏(G) → 声音

**做什么**：游戏菜单 → 点 **「声音」**，看勾出现/消失。

- **算通过**：同上，勾会变，菜单会消失。
- **算失败**：菜单残留。
- **失败时发回来**：截图。

### 步骤 7-7　游戏(G) → 最佳成绩

**做什么**：游戏菜单 → 点 **「最佳成绩」**。

- **算通过**：弹出**「扫雷统计信息」窗口**（左边一列难度、中间一块、右边几行数字、底下两个按钮）。
- **算失败**：没弹、或者弹出来是一张**空白的框**。
- **失败时发回来**：截图。

### 步骤 7-8　游戏(G) → 颜色(C)

**做什么**：游戏菜单 → 点 **「颜色(C)」**。

## 11. 怎么看缩放档位（hilog）

**这一节是给想看「程序内部到底怎么算的」的你。** 前面 12 节都不需要碰它。

### 11.1 先说明一件事：捏合**不会**打日志

双指捏合改缩放时，程序**没有**打「捏合 档位n=」这种日志（**这个功能没做**）。
所以想看捏到了第几档，要**用折叠来把它逼出来** —— 折叠会触发一次重新布局，
重新布局**会**打一行日志，那行里就有档位。

### 11.2 抓日志

**做什么**：在 PowerShell 里粘这两行、回车（第二条会一直刷，按 `Ctrl+C` 停）：

```powershell
& $hdc -t $d shell hilog -r            # 先把旧日志清掉
& $hdc -t $d shell hilog -x | Select-String 'JSAPP'
```

- **算通过**：屏幕上滚出一行一行的日志，其中能看到类似这样的一行：

```
[GameController] 布局 画布=... 密度换算=... 适配档n=3 当前档n=3 unit=6 格边=108px 棋盘原点=(...) HUD=0 状态条上沿=...px 盘面=9x9 雷=10
```

- **算失败**：一行都没有 → 说明应用没在跑（先启动一次应用再抓），或者 `-r` 清完之后没操作任何东西。

### 11.3 看捏合前后的档位

**做什么**：
1. 启动应用，展开成内屏 → 抓一次日志，记下 `当前档n=` 的值（比如 `n=3`）
2. **双指捏合放大**几下
3. **把手机折起来，等 2 秒**（这一步会触发一次重新布局，打出新的布局日志）
4. 再抓一次日志，记下新的 `当前档n=`

- **算通过**：两次的 `当前档n=` **不一样**（捏合确实改了档位），
  而且折叠之后**新档位被保留下来了**（这正好也验了第 4 节的「折叠保住视角」）。
- **算失败**：两次 `当前档n=` 一样（捏合没生效）。
- **失败时发回来**：两次的日志。

### 11.4 日志里能看懂的几个字段

| 字段 | 意思 |
|---|---|
| `适配档n=` | 「整盘刚好放下」需要的档位（程序自己算的） |
| `当前档n=` | **现在实际用的档位** —— 捏合改的就是它 |
| `unit=` | 每个逻辑单位占多少设备像素（= 2 × 档位） |
| `格边=` | 一格多少设备像素 |
| `棋盘原点=(x,y)` | 棋盘左上角在画布里的位置（**负数是正常的**，表示棋盘左边超出了屏幕） |
| `HUD=` | 1 表示状态条被「钉」在屏幕底边（纵向装不下时） |
| `盘面=行x列` | **这局棋多大**（设备无关，可以直接拿来判断有没有真的开出这一局） |
| `雷=` | 这局有多少个雷 |

> `盘面=` 和 `雷=` 这两个是**设备无关**的（不随屏幕尺寸变），
> 所以断言「有没有真的开出 24×30 这一局」要看这两个，**不要**看格边和原点。

## 12. 失败了把什么发回来

**不用你分析原因。** 每一节都写了「失败时发回来」，按那一行说的发就行。

汇总一下，一次性发这些最省事：

1. **手机截图**（能复现问题的那个画面）
2. **电脑上的日志**（第 11 节那条命令的输出）
3. **你当时在做哪一步**（比如「4-2 折起来之后旗没了」）
4. 顺手说一句**机型和系统版本**（设置 → 关于手机 里能看到）

**哪些是已知问题、不用报**：

| 现象 | 说明 |
|---|---|
| 帮助框里写着「右键插旗」 | 原版 Win7 的说明文字，手机上对应长按（见 0.1） |
| 状态条上的**时钟**和**雷图标**点不动 | **原版就是装饰**，点它没反应是正确的（见 `docs\SPEC.md` §8 第 7 条） |
| 颜色框里「随机选择…」那个复选框是灰的 | **原版就置灰**，点它没反应是正确的（见 8.6） |
| 没有「笑脸」按钮 | **Win7 就没有笑脸**（XP 才有），这是对的 |
| 30 列的局棋盘超出屏幕、要拖才能看全 | **设计如此**，不是 bug（见 5.5） |
| 捏合时没有日志 | 这个功能没做（见 0.2、11.1） |
| 一点声音都听不到 | 音效**从来没实测过**，请在下面写一句（见 0.3） |
