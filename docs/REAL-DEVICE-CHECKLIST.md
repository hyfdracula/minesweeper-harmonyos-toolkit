# 真机验收清单（Pura X Max）

> **给谁看**：手上只有一台华为 Pura X Max 典藏版、不写代码的你。
>
> **设备**：内屏 2584 × 1824（横屏），外屏 1323 × 1936，密度 2.75。
>
> **这一版是 2026-11-02 晚更新之后的版本**（前一版是 2026-11-01 真机实测之后的版本）。
>
> **全篇只剩 4 件要你做，大约 20 分钟** —— 这 4 件从 2026-11-01 起就没变过，
> 因为**只有人能做**（声音、捏合手感、折叠保局面、外屏点得准不准）。

## 0. 2026-11-02 晚上新增的（你不用做什么，只是让你知道程序改了哪些）

| 改了什么 | 为什么要改 | 对你有没有影响 |
|---|---|---|
| **状态条液晶屏的「1」重画了** | 之前的画法（带小旗、衬线）在放大 8 倍后看起来像「0 的右半边」。现在按标准七段：**「1」= 右边两根小竖杠，中间有缝** | 你看计时器/雷数里的「1」时，形状变了；数字本身没变 |
| **折叠换屏时密度重新取** | 原来密度只在打开时读一次，换屏后不刷新 → 整块棋盘和状态条会按旧密度画 | 折叠/展开后棋盘大小会重新算一次（这是应该的） |
| **折叠换屏时棋盘状态保留** | 实测（Mate X7 折叠屏模拟器）：展开 2210×2208 → 折叠 1080×2236，**棋子、旗子、数字、秒数全部保住**，不用重开 | 你折叠时局面不会丢 |
| **计数器的反解器修了** | 跑测器读不出数字（不是程序画错，是测量工具算错） | 无 |
| **七段渲染器补了单元测试** | 之前这块只有肉眼检查，改坏了没人知道 | 无 |

**自动验过的成绩（2026-11-02 晚）**：

| 范围 | 结果 |
|---|---|
| 引擎单元测试 | **59 / 59** |
| 七段数码管渲染器单元测试 | **11 / 11**（新增） |
| Mate 90 Pro 模拟器 · 四域 86 条 | **86 / 86**（counter 修好后补跑 3/3） |
| Mate X7 折叠屏模拟器 · 四域 86 条 | 见 `docs\HANDOVER.md` 的最新汇总 |
| 折叠开合 · 布局重排 + 局面保留 | **通过**（Mate X7 模拟器实测，证据图在 `docs\verify\X7_*.jpeg`） |

**Codex 对抗性复审**：裁定 **BLOCKER**（来源：由 P0/P1 严重级别标记推断，不是模型直接写的 VERDICT 行）。
三条意见（密度算错、Ability 里那个回调根本不会被调用、标志位没清）**都已修**，
并补了新的自动化测试和模拟器实测。

### 1.3 真机上的版式（这一条已经确认，不用你量）

真机的布局日志长这样（原文抄的）：

```
[GameController] 布局 画布=2584x1644px 密度换算=0.3636 适配档n=4 当前档n=4 unit=8 格边=144px 棋盘原点=(644,75) HUD=0 状态条上沿=1371px 盘面=9x9 雷=10 外观=蓝/扫雷
```

这一行**逐项都对得上代码**（已逐项核对）：

- 密度换算 0.3636 的倒数 = **2.75**，就是这台机器的密度
- 格边 144 px = 18 参照像素 × unit 8；**144 px 约 52 vp**，比模拟器上的 72 px 大 ——
  真机上格子大，**用手指点得准**
- 棋盘原点 x = (2584 − 9×144) ÷ 2 = **644**，**横向正好居中**
- 棋盘原点 y = 菜单栏 58 px + (1586 − 1296 − 256) ÷ 2 = **75**，**纵向正好居中**
- 状态条上沿 1371 = 75 + 1296，**和棋盘底边接得上**

所以真机上**初级局是上下左右都居中的**，状态条**不会被裁掉**。

### 1.4 顺手修掉的一处旧账

帮助框里那句「右键插旗」是**原版 Windows 7 的说明文字**。
手机上没有右键，插旗是**长按** —— 这是有意改的，不是 bug。
另外状态条上的**时钟**和**雷图标**点不动、颜色框里那个**灰掉的复选框**、**没有笑脸按钮**，
这三样都是**原版就那样**，不是缺功能。

## 2. 还需要你手动确认的（只剩这 4 件）

每一件都写了「算什么通过」「算什么失败」「失败了发什么回来」。

### 2.1 声音（从来没听过）

**这是唯一一件「全新」的**。代码写了音效，但**没有人听过它到底响不响**。

**做什么**：展开成内屏，开一局，然后依次做三件事，每做一件停一下听：
1. 点开一格 —— 应有「翻开」的一声
2. 长按插一面旗 —— 应有「插旗」的一声
3. 故意踩一个雷 —— 应有「爆炸」的一声

- **算什么通过**：三声（或至少一声）都能听见，而且**不叠音**、不刺耳。
- **算什么失败**：**一声都没有**；或者声音重叠在一起糊成一片；或者声音又长又不停。
- **失败了发什么回来**：说一声「我什么都没听到」/「声音叠在一起」就行，**不用截图**。

> **说明**：如果只是「没听清」，请在**安静的环境**再试一次再报。

### 2.2 双指捏合缩放

**做什么**（三小步，每步都照做）：

1. **展开成内屏**，在棋盘上**双指张开**（像放大照片），一直张开到最大，等 1 秒
2. 再**双指捏拢**（像缩小照片），捏到最小，等 1 秒
3. 捏到小之后，**一根手指按住棋盘往左拖**，再往右拖

- **算什么通过**（三条都要满足）：
  1. 格子**明显变大又变小**，而且格子**始终是方的**（没被拉扁）
  2. 捏到最小的时候，**整盘棋基本能看全**
  3. **单指拖动，棋盘跟着手指走**，能看到原本在屏外的那些格子
- **算什么失败**：捏了没反应；或者格子变形；或者拖不动、或者一拖就「飞」出去找不回来。
- **失败了发什么回来**：**捏之前**和**捏之后**各截一张图（两张都要），加上第 3 节的日志。

> **顺便说**：30 列的局在窄屏上装不下，程序会**故意**让棋盘超出屏幕边，靠拖动看 ——
> 这是**设计如此**，不是溢出 bug。

### 2.3 折叠开合，局面保不保得住

**这一节最重要** —— 折叠屏是你最在意的点。
折一下、展开一下，**翻开的格子、插的旗、计时、雷数**都得还在。

**做什么**：

1. 展开成内屏，做三件事：**点开中间一格**、在两个没翻开的格子上**长按插旗**、
   然后**等计时跑到 5 秒以上**
2. **把手机折起来**（用外屏），等 2 秒，看四条：
   - 翻开的格子**还是翻开的**
   - 那两面红旗**还在**（还是红旗，不是问号）
   - 计时**继续在走**（不是从 0 开始，也没停住）
   - 雷数**还是原来的数**（没回到 10）
3. **再展开**回内屏，等 2 秒，看同样那四条

- **算什么通过**：第 2 步和第 3 步的**四条全部保持住**。
- **算什么失败**：任何一条不满足（旗没了、计时归零、雷数重置、翻开的格子合上了）。
- **失败了发什么回来**：**折起来那一屏**和**展开后那一屏**两张截图（都要），加第 3 节的日志。

### 2.4 内屏与外屏来回切换

**做什么**：

1. 展开成内屏 → 等 2 秒 → 看画面
2. 折起来（外屏）→ 等 2 秒 → 看画面
3. 再展开 → 等 2 秒 → 看画面

- **算什么通过**：
  - 内屏：**横屏**，菜单栏左上、棋盘中间、状态条底部，**三样都在屏内**，格子不歪
  - 外屏：**竖屏小屏**，菜单栏、棋盘、状态条**三样都在屏内**，格子**不歪、不变形**
  - 再展开：回到横屏，棋盘还在
- **算什么失败**：黑屏；或者卡在展开态不变；或者有任何一块被**裁掉**；或者格子被拉扁。
- **失败了发什么回来**：**三个画面各截一张**（展开 / 折起 / 再展开），加第 3 节的日志。

> **再补一个**：折起来（外屏）之后，**点一下**某个格子，
> 看看**翻开的是不是就是你点的那个**（周边一圈可能跟着一起翻开，那是正常的）。

## 3. 怎么抓日志（hilog）

**只有上面 4 件失败时才需要抓。** 抓法：

```powershell
$hdc = 'D:\software\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe'
$d   = '6HR0226409003317'   # Pura X Max 的序列号

& $hdc -t $d shell hilog -r            # 先把旧日志清掉
& $hdc -t $d shell hilog -x | Select-String 'JSAPP'
```

第二条会一直刷，按 `Ctrl+C` 停。**操作之前先清、之后再抓**，抓到的才是你刚才那一下。

### 3.1 日志长什么样

一次操作会产生这几类行（2026-11-01 在真机上实测到的）：

| 日志 | 什么时候打 | 你能从中看出什么 |
|---|---|---|
| `[GameController] 布局 画布=… 当前档n=… 格边=…px 棋盘原点=(…) 盘面=… 雷=… 外观=蓝/扫雷` | 每次重新布局 | **版式**：格子多大、棋盘在哪、这局多大、什么配色 |
| `[Touch] 捏合 档位n=…` | **每次捏合** | **捏到了第几档**（2026-11-01 新加的） |
| `[Touch] 平移 dx=… dy=…` | 每次拖动 | 拖动了多远 |
| `[GameController] 新局 …x… 雷=…` | 开新局 | 开的是多大一局 |
| `[DealIn] 发牌动画结束 elapsed=…` | 发牌动画结束 | 动画跑了多久 |
| `[Menu] 菜单动作 …` | 点菜单项 | 你点到的是哪一项 |
| `[Dialog] 打开 胜利/失败` | 弹结束框 | 弹的是**赢**的框还是**输**的框 |
| `[Dialog] 点击按钮 …` | 点对话框按钮 | 点了哪个按钮 |
| `[Dialog] 点到缩略图 …` | 点颜色框的缩略图 | 点到了第几枚 |
| `[Dialog] 应用外观 …` | 颜色框按确定 | 外观**生效**了（颜色变成什么） |
| `[GameStats] 外观已保存 board=… game=…` | 外观存盘 | 外观**记住了** |

> **最有用的一条**：`[GameController] 布局 … 盘面=9x9 雷=10 外观=蓝/扫雷`
> 里的 `盘面`、`雷`、`外观` 是**设备无关**的，
> 所以**要判断「有没有真的开出 24×30 这一局」「外观有没有生效」，看这三个字段**，
> 不要去看格边和棋盘原点（那两个随屏幕尺寸变）。

### 3.2 捏合的档位怎么看（今天起可以直接看了）

在这之前捏合**不打日志**，得靠折叠把日志逼出来。
**2026-11-01 已经加了 `[Touch] 捏合 档位n=…`**，所以：

1. 打开应用，等日志里出现一行 `[GameController] 布局 … 当前档n=…`（记下这个 n）
2. **双指捏合**几下
3. 再看日志里有没有新的 `[Touch] 捏合 档位n=…`（记下这个 n）

- **两个 n 不一样** = 捏合生效了
- **两个 n 一样** = 捏合没生效（这就是失败）

## 4. 失败了把什么发回来

**不用你分析原因。** 汇总一下，一次性发这些最省事：

1. **手机截图**（能复现问题的画面）
2. **第 3 节抓的日志**（先清再抓）
3. **你当时在做哪一步**（比如「2.3 折起来之后旗没了」）
4. 顺手说一句**你听没听到声音**（这一条只有你能回答）

### 4.1 不用报、属于原版就这样的

| 现象 | 说明 |
|---|---|
| 帮助框里写着「右键插旗」 | 原版 Win7 的说明文字，手机上对应**长按**（见 1.4） |
| 状态条上的时钟和雷图标点不动 | **原版就是装饰**，点它没反应是正确的 |
| 颜色框里「随机选择…」那个复选框是灰的 | **原版就置灰**，点它没反应是正确的 |
| 没有「笑脸」按钮 | **Win7 就没有笑脸**（XP 才有），这是对的 |
| 30 列的局棋盘超出屏幕、要拖才能看全 | **设计如此**，不是 bug（见 2.2） |
| 某个对话框在真机上和模拟器长得不一样 | **待测** —— 对话框只在模拟器上验过，真机上的精确像素还没量（见 `docs\REAL-DEVICE-2026-11-01.md`） |
