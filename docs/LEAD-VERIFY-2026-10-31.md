## 1. 帮助窗口的 Win7 原版插图：像素级成立

### 背景

帮助框从 320×210 纯文字改成 584×280，左侧放 Win7 原版插图 `helpBoard.png`（256×192，微软原图，**1:1 图**）。
资源：`entry\src\main\resources\rawfile\helpBoard.png`（69646 字节，与源文件字节一致）。

### 踩到的两个坑（都是我自己写的）

**坑 1：`SpriteAtlas.drawWhole` 的 vp/设备像素换算方向写反。**
原写法 `devX / pxScale`，而 `pxScale = 1/density`，设备像素 → vp 应该是「乘 pxScale」。
结果图被画到画布外 3.125 倍远的地方，**看上去就是「资源读到了但什么都没画」**。
图集日志是正常的（`helpBoard.png 读到 69646 字节`、`图集加载完成 ... help=true`），所以不能靠日志判断，
只能靠截图。已修为 `devX * pxScale`（commit `c130326`）。

**坑 2：1:1 图不能套 `SPRITE_SCALE`。**
blueSheet 等是 2 倍存（`SPRITE_SCALE = 2`），源矩形要 `× SPRITE_SCALE × pxScale`；
helpBoard 是 1:1，套 ×2 会裁到图外画成空白。故新增 `SpriteAtlas.drawWhole()`，源矩形不乘 `SPRITE_SCALE`。

### 实测（Mate 90 Pro，127.0.0.1:5557，commit c130326）

- 画布 1280×2598px，密度 3.5，画布顶比屏幕顶低 **139px**。
- 对话框缩放 `s = min(2, 3.5, (1280-32)/584, (2598-32)/280) = 2` → 放大倍数 `k = floor(s) = 2`。
- 预测插图左上角（屏幕）= `(ox + 16*s, oy + 37*s)`，其中 `ox = (1280-584*2)/2 = 56`、`oy = (2598-280*2)/2 + 139 = 1158`
  → 预测 **(88, 1232)**。
- **穷举匹配**（k=1..4、位置逐 4px 扫描）→ 最佳 `k=2`、位置 **(88, 1230)**，与预测差 2px（在取整范围内）。
- 逐像素比对（截图裁切 vs 源图 ×2 最近邻）：
  - 逐像素差**中位数 (0, 0, 0)** ✓
  - 均值 RGB：截图 `[132.97, 148.28, 189.40]` vs 源图 `[132.60, 148.17, 189.37]`（差 ≤ 0.4）✓
  - 最佳 1px 对齐（dy = -1）后平均通道差 **5.62**，残差全部来自 **截图是 JPEG（有损）**的边缘振铃。
- 结论：**整数 2 倍、最近邻、真像素级** ✓
  证据图：`docs\verify\HELP_AB.png`（左=源图×2，右=截图裁切，并排肉眼比对一致）、
  `docs\verify\HELP_p90.jpeg`（设备原图）。

> 教训：截图是 JPEG，用「差异像素占比」当判据会被压缩噪声带偏。
> 判像素级要看 **逐像素差的中位数** 和 **均值通道差**，不要看差异像素占比。
