### 0.1 已定的两处口径（lead 拍板）

- **「1」用标准七段的 b + c**（掩码 **`0x06`**）：不加旗、不加衬线、不连成一根。

### 1.0 第六版定案（2026-11-02）：标准七段，一个装饰都不加

| 版本 | 「1」的画法 | 结果 |
|---|---|---|
| 第四版 | b + c + 旗(SEG_FLAG) + 底横(SEG_BASE1)，掩码 `0x186` | 真机上被读成「0 的右半边」 |
| 第五版 A | b+c 连成一整根竖笔 | 断成两截的观感消失，但形状不像 Win7 |
| 第五版 B | 整根竖笔 + 左上小方点 + 短底横 | 在 8 倍放大下连成一个「]」形，仍不像「1」 |
| **第六版（现用）** | **标准 b + c 两根小竖杠，中间有缝，掩码 `0x06`** | **和计算器液晶屏一致，一眼是「1」** |

**为什么回到标准七段**（用户 2026-11-02 原话：「一个液晶屏就 7 个地方能显示，
规定好七个杠杠必须一起显示就行了」）：

- Win7 原版 `helpBoard.png` 的「18」里，「1」确实带旗和衬线，但那是**在 31 像素宽的面板里**，
  旗只有 5 像素，看着是一根小斜杠。
- 我们的面板放大 8 倍（su=8），同样的比例就变成 **24 像素的横杠**，
  和竖笔、底横一凑，字形就是「上横 + 右竖 + 下横」= **半个「0」**。
- 所以自定义段（SEG_FLAG / SEG_BASE1 / SEG_ONEBAR）**全部删掉**，
  渲染器里只剩 a..g 七根杠，数字 = 这七根杠的组合。

**几何为什么定成 9×11、笔画 1**：原版面板 40 单位宽、数字格 13 宽，
而我们的槽位要放进 33 单位的彩色内区里；笔画粗到 2~3 个单位时，
「0」会糊成一坨，笔画 1 个单位时每个段都还分得开（真机、模拟器实拍均已确认）。

**反解器（`tools/sevenseg_read.py`）**同步改成：用**白色数字本身**反推格位
（墨迹右边缘 = 最后一格右边界；墨迹竖直中心 = 格子中心），
不再拿面板框当内区（框含外沿斜角高光，比内区宽 12 像素，会偏 1.5 个单位）。

### 1.1 面板与槽位（单位：**参考像素**，即本项目 Theme 里的逻辑单位）

| 项 | 值 | 说明 |
|---|---|---|
| 凹槽面板 | **40 × 21** | `Theme.RECT_COUNTER = [0,580,40,21]`，与 `Theme.STRIP_PANEL_W/H`（40/21）一致 |
| 槽位数 | **3** | 百位 / 十位 / 个位 |
| 槽距 | **13** | 第 i 槽的 x = **0 + 13·i**，即 **0 / 13 / 26** |
| 数字格宽 | **12** | 每槽左右各留 1 像素（避开面板边框），三个格子占面板内 **0..11 / 13..24 / 26..37** |
| 数字格高 | **16** | 上下留边；面板 21 高 → 数字占 y 2..17 |
| 数字格在面板内的 y | **2** | (21 − 16) / 2 = 2.5，取 2 |
| 对齐 | **右对齐，不补零** | 2 位数占右两槽，左槽空着 |
| 负号 | **只亮中段 g** | 占「紧挨数字左边那一槽」 |
| 显示区间 | **[-99, 999]** | 超出就钳到端点 |

**为什么第 0 槽是 x=0 而不是 XP 的 x=1？**

面板精灵（`RECT_COUNTER`，40×21）**右缘有 2 个参考像素的斜角高光**（右上到右下的倒角）。
按 XP 的 +1 偏移，第三个格子会占到 x=38，右竖段正好压在那道斜角上，
视觉上糊成一片 —— **2026-10-31 在 Mate X7 上实测：「0」的右竖段和面板斜角连成了一块**。
改成 x=0 之后，三个格子占面板内 0..11 / 13..24 / 26..37，右边正好停在斜角内侧。
（XP 版的槽位 17/30/43 落在它自己 40 宽面板的 16..56 里，也是贴着右边，
但 XP 的面板**没有**这道 2 像素斜角，所以照抄会压边。）

### 1.2 段的坐标（**数字格局部坐标**，原点在数字格左上角；格 12 宽 × 16 高）

| 段 | 名称 | x | y | 宽 | 高 | 备注 |
|---|---|---|---|---|---|---|
| a | 上横 | 3 | 0 | 6 | 2 | |
| b | 右上竖 | 9 | 2 | 3 | 5 | 「1」的竖笔用它 |
| c | 右下竖 | 9 | 9 | 3 | 5 | 「1」的竖笔用它 |
| d | 下横 | 3 | 14 | 6 | 2 | 标准下横；**「1」不用它**（见 SEG_BASE1） |
| e | 左下竖 | 0 | 9 | 3 | 5 | |
| f | 左上竖 | 0 | 2 | 3 | 5 | |
| g | 中横 | 3 | 7 | 6 | 2 | **负号也用这一段** |
| **旗** | SEG_FLAG（第 8 段） | **7** | **2** | **2** | **2** | 只给「1」用；**紧挨 b 竖段（x 9..11）的左沿**，高度对齐 b 的上端；不属于标准七段 |
| **底横** | SEG_BASE1（第 9 段） | **7** | **14** | **5** | **2** | 只给「1」用；在**最下一行**（y = CELL_H − TH），**以竖笔为中心**向两侧伸出；不属于标准七段 |

校验：
- 竖向：2 + 5 + 2 + 5 + 2 = **16** = 格高
- 横向：3 + 6 + 3 = **12** = 格宽
- 横段长度 = 12 − 2×3 = 6，正好卡在两根竖段之间；
  角上是**斜角相接**（横段末行与竖段首列错开一格，形成 1 px 对角缺口），
  和 `helpBoard.png` 里「8」的角部处理一致。
- 「1」的两笔：旗在 x 7..8（**紧贴**竖笔左沿 x=9），底横在 x 7..11（竖笔占其中 9..11） 

**换算到面板坐标**（面板内，40×21）：

| | 槽 0 | 槽 1 | 槽 2 |
|---|---|---|---|
| 数字格 x | 0..11 | 13..24 | 26..37 |
| 数字格 y | 2..17 | 2..17 | 2..17 |

面板右缘的 2 像素斜角在 x 38..39，数字最右只到 37，留 1 像素余量。

### 1.3 数字 → 段组合

| 数字 | 亮段 | 掩码 |
|---|---|---|
| 0 | a b c d e f | 0x3F |
| **1** | **b c**（标准七段，中间有缝） | **0x06** |
| 2 | a b g e d | 0x5B |
| 3 | a b g c d | 0x4F |
| 4 | f g b c | 0x66 |
| 5 | a f g c d | 0x6D |
| 6 | a f g e c d | 0x7D |

（位序：a=1, b=2, c=4, d=8, e=16, f=32, g=64。**旗(128)/底横(256)/整根竖笔(512) 三个自定义段已全部删除**）

而原图的底横是**以竖笔为中心**向两侧伸出的（§2 的逐像素读数：x 61..65，竖笔在 x=63），
所以单独加了第 9 段 SEG_BASE1（x 7..11）。

### 3.2 反推 / 中置信部分（明确标出来）

**（g）段的粗细绝对值** —— **反推**。

`helpBoard.png` 的计数器只有 9 px 高，插图又是手绘的（凹槽 27×9 对应真实 40×21，
横向比 0.675、纵向比 0.43，**不是等比缩放**），所以它只能给**比例**，给不了绝对值。
绝对值取自 XP 的字格（13 宽 × 23 高、段粗 3），按 Win7 的格高 16 缩成 **tv=3 / th=2 / hl=5**。

**（h）数字格 12×16、面板内 y 偏移 2** —— **反推**，两条依据：
1. `RECT_COUNTER` 精灵四周有 **1 个逻辑像素的边框**（左上暗边、右下亮边），
   数字压上去会盖住边框 → 水平每槽留 1 像素（格宽 12）、上下留边（格高 16）；
2. 原版帮助插图里数字占凹槽 9 像素中的 7 像素 → 21 × 7/9 ≈ 16。

**（i）「1」的旗与底横** —— **已按原图修正**（此前是待复核项）。
原图的旗是**紧挨竖笔左上角**的（原图格宽只有 5 像素，竖笔在 x=63、旗在 61..62，相邻）。
先前实现把旗放在格子局部 x=1（竖笔 b/c 在 x=9..11），相距 7 个参考像素，是**脱开的**；
底横复用标准 d（x 3..8）也落在竖笔**左侧**、不是正下方。
**现已改成**：
- 旗：`cellX + CELL_W - TV - 2`（= 格子局部 **x 7..8**，紧贴竖笔左沿 x=9），高度对齐 b 的上端；
- 底横：新增第 9 段 `SEG_BASE1`，`cellX + CELL_W - TV - 2`、宽 `TV + 2`（= 格子局部 **x 7..11**），
  在最下一行 y = `CELL_H - TH`，以竖笔为中心向两侧伸出；
- 「1」的掩码随之从 `0x8E`（b+c+d+旗）改成 **`0x186`**（b+c+旗+底横，**去掉标准 d**）。

（剩下的 1 像素细节：底横 x 7..11 的中心在 x=9，而竖笔 x 9..11 的中心在 x=10，

### 4.3 换算是怎么成立的

- `this.v(px)` = `Math.round(px) * this.pxScale`（GameController 第 232-233 行），设备像素 → vp；
- 面板是用 `drawLogical(..., timeX, timeY, u)` 画的，设备尺寸 = 40·u × 21·u，

- `SevenSeg` 内部用 `pxScale = sVp / sDev` 反推回设备像素并取整，
  保证段的边落在**整数设备像素**上（不虚）。

### 7.2 真正会让数码管发糊的原因（已修）

段宽只有 2~3 个参考像素，乘上缩放系数（unit = 一个参考像素对应多少设备像素）
之后，在**分数密度**的屏幕上（折叠屏 2.75 倍 / 3.5 倍密度）常常落在半个像素上，
画布会做抗锯齿 → 数码管看起来发虚。

修法（应用仓提交 `b798a60`）：`SevenSeg.rect()` 改成**把每条边取整到整数设备像素**
（取整的是**边**不是宽 —— 相邻两段共用一条边，两边各自取整会得到同一个值，
所以接缝仍然严丝合缝，不会多出绿缝也不会叠出白块）。

```ts
const x0 = Math.round(devX0 + refX * sDev);
const y0 = Math.round(devY0 + refY * sDev);
const x1 = Math.round(devX0 + (refX + refW) * sDev);
const y1 = Math.round(devY0 + (refY + refH) * sDev);
ctx.fillRect(x0 * pxScale, y0 * pxScale, (x1 - x0) * pxScale, (y1 - y0) * pxScale);
```
