## 1. 几何表

### 1.1 面板与槽位（单位：**参考像素**，即本项目 Theme 里的逻辑单位）

| 项 | 值 | 说明 |
|---|---|---|
| 凹槽面板 | **40 × 21** | `Theme.RECT_COUNTER = [0,580,40,21]`，与 `Theme.STRIP_PANEL_W/H`（40/21）一致 |
| 槽位数 | **3** | 百位 / 十位 / 个位 |
| 槽距 | **13** | 第 i 槽的 x = **0 + 13·i**，即 **0 / 13 / 26** |
| 数字格宽 | **12** | 每槽左右各留 1 像素（避开面板边框），三个格子占面板内 **0..11 / 13..24 / 26..37** |
| 数字格高 | **16** | 上下留边；面板 21 高 → 数字占 y 2..17 |
| 数字格在面板内的 y | **2** | (21 − 16) / 2 = 2.5，取 2 |
| 对齐 | **右对齐，不补零** | 2 位数占右两槽，左槽空着 |
| 负号 | **只亮中段 g** | 占「紧挨数字左边那一槽」 |
| 显示区间 | **[-99, 999]** | 超出就钳到端点 |

**为什么第 0 槽是 x=0 而不是 XP 的 x=1？**

面板精灵（`RECT_COUNTER`，40×21）**右缘有 2 个参考像素的斜角高光**（右上到右下的倒角）。
按 XP 的 +1 偏移，第三个格子会占到 x=38，右竖段正好压在那道斜角上，
视觉上糊成一片 —— **2026-10-31 在 Mate X7 上实测：「0」的右竖段和面板斜角连成了一块**。
改成 x=0 之后，三个格子占面板内 0..11 / 13..24 / 26..37，右边正好停在斜角内侧。
（XP 版的槽位 17/30/43 落在它自己 40 宽面板的 16..56 里，也是贴着右边，
但 XP 的面板**没有**这道 2 像素斜角，所以照抄会压边。）

### 1.2 段的坐标（**数字格局部坐标**，原点在数字格左上角；格 12 宽 × 16 高）

| 段 | 名称 | x | y | 宽 | 高 | 备注 |
|---|---|---|---|---|---|---|
| a | 上横 | 3 | 0 | 6 | 2 | |
| b | 右上竖 | 9 | 2 | 3 | 5 | |
| c | 右下竖 | 9 | 9 | 3 | 5 | |
| d | 下横 | 3 | 14 | 6 | 2 | 「1」用它当底横 |
| e | 左下竖 | 0 | 9 | 3 | 5 | |
| f | 左上竖 | 0 | 2 | 3 | 5 | |
| g | 中横 | 3 | 7 | 6 | 2 | **负号也用这一段** |
| **旗** | SEG_FLAG（第 8 段） | **1** | **2** | **2** | **2** | 只给「1」用；**不属于标准七段** |

校验：
- 竖向：2 + 5 + 2 + 5 + 2 = **16** = 格高 
- 横向：3 + 6 + 3 = **12** = 格宽 
- 横段长度 = 12 − 2×3 = 6，正好卡在两根竖段之间；
  角上是**斜角相接**（横段末行与竖段首列错开一格，形成 1 px 对角缺口），
  和 `helpBoard.png` 里「8」的角部处理一致。

**换算到面板坐标**（面板内，40×21）：

| | 槽 0 | 槽 1 | 槽 2 |
|---|---|---|---|
| 数字格 x | 0..11 | 13..24 | 26..37 |
| 数字格 y | 2..17 | 2..17 | 2..17 |

面板右缘的 2 像素斜角在 x 38..39，数字最右只到 37，留 1 像素余量。

### 3.2 反推 / 中置信部分（明确标出来）

**（g）段的粗细绝对值** —— **反推**。

`helpBoard.png` 的计数器只有 9 px 高，插图又是手绘的（凹槽 27×9 对应真实 40×21，
横向比 0.675、纵向比 0.43，**不是等比缩放**），所以它只能给**比例**，给不了绝对值。
绝对值取自 XP 的字格（13 宽 × 23 高、段粗 3），按 Win7 的格高 16 缩成 **tv=3 / th=2 / hl=5**。

**（h）数字格 12×16、面板内 y 偏移 2** —— **反推**，两条依据：
1. `RECT_COUNTER` 精灵四周有 **1 个逻辑像素的边框**（左上暗边、右下亮边），
   数字压上去会盖住边框 → 水平每槽留 1 像素（格宽 12）、上下留边（格高 16）；
2. 原版帮助插图里数字占凹槽 9 像素中的 7 像素 → 21 × 7/9 ≈ 16。

**（i）「1」的旗摆在哪** —— **实现与原图仍有差距**。
原图里旗是**紧挨竖笔左上角**的（原图格宽只有 5 像素，竖笔在 x=63、旗在 61..62，相邻）；
当前实现的旗在**格子局部 x=1**（竖笔 b/c 在 x=9..11），两者相距 7 个参考像素，旗是**脱开的**。
底横 d 同理：标准 d 落在 x 3..8，在竖笔的**左侧**，不是正下方。
两处都是「七段 + 一撮旗」这种近似画法的固有代价。
若要在真机上更贴近原图，把旗改成紧挨 b 竖段左上角即可（`cellX + CELL_W - TV - 2`），
本实现取 `cellX + TV - 2`（= 格子左上角）。**这是待 lead 复核的一项。**

**（j）1 位负数的负号位置** —— 插图只有「-40」一例。
**已定**：负号紧挨数字左边那一槽（-4 → `[空][-][4]`），与「-40」= `[-][4][0]` 同一套规则。
（XP 的代码是把负号固定放最左槽、且用补零的 `[负][0][4]`，不照抄。）

**（k）溢出钳位** —— 三位最多 999；负数最多到 -99（插 99 面旗）。
超出就钳到端点（-381 显示 **-99**，不是 -81 —— 显示低三位等于显示一个错的数）。
XP 的代码在这个区间是坏的（`LeftFlags % 100` 对负数会得到负数下标），所以不能照抄。

**（l）灭段不画** —— 原版凹槽里看不到暗段，按原样。

## 4. 接线说明

### 4.1 调用签名

```ts
static draw(ctx: CanvasRenderingContext2D, value: number, xVp: number, yVp: number,
  sVp: number, sDev: number): void
```

| 参数 | 含义 |
|---|---|
| `ctx` | Canvas 上下文 |
| `value` | 要显示的整数，**可负**；小数截断；超出 [-99, 999] 会钳到端点；NaN/Infinity 不画 |
| `xVp` | **凹槽面板左上角**在 **vp**（Canvas 单位）里的位置 |
| `yVp` | 同上，纵坐标 |
| `sVp` | **一个参考像素等于多少 vp**（= 参考像素→vp 的总缩放） |
| `sDev` | **一个参考像素等于多少设备像素**（本例只用来把段的边对齐到整数设备像素） |

面板内偏移与对齐规则（都已写死在 `SevenSeg` 里，调用方不用管）：

- 数字**右对齐**进 3 个槽（槽位在面板内 x = **0 / 13 / 26**，每槽的格子 12 宽）；
- 数字格 12×16，**面板内 y 偏移 2**，四边都留出边距，不压面板边框、也不压右缘斜角；
- 负号占数字左边那一槽；
- 灭的段不画。

### 4.3 换算是怎么成立的

- `this.v(px)` = `Math.round(px) * this.pxScale`（GameController 第 232-233 行），设备像素 → vp；
- 面板是用 `drawLogical(..., timeX, timeY, u)` 画的，设备尺寸 = 40·u × 21·u，
  所以**一个参考像素 = u 个设备像素 = u·pxScale 个 vp** ⇒ `sVp = u * this.pxScale`、`sDev = u`；
- `SevenSeg` 内部用 `pxScale = sVp / sDev` 反推回设备像素并取整，
  保证段的边落在**整数设备像素**上（不虚）。
