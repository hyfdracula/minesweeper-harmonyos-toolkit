## 0. 结论速览（先回答三个问题）

**问题一：自定义雷数上限到底是多少（全局 668 还是按格数）？**

**代码是「按盘面尺寸」，不是全局 668。** 面板层与引擎层都用
`min(668, (行-1)*(列-1)+1)`，所以 9×9 的上限是 65、16×16 是 226、24×30 才是 668。

但 **SPEC §8-2 的决定写的是「面板层保留全局 668 的输入上限，引擎层按尺寸夹取」**，
与代码不一致（详见 P2）。需要裁决：改代码还是改规格。

**问题二：自定义局有没有被错误计入统计？**

**没有。核实通过。** `GameStats.record()` 是全工程唯一会动
`played / won / currentStreak / maxStreak / bestSeconds` 的地方，而它被
`if (!this.customGame)` 包住（`GameController.ets:1007-1011`）。
自定义局既不计「已玩游戏/已胜游戏/百分比」，也不占连胜/连败，更不会写进任何难度的最佳成绩；
`isNewBest` 也被同一标志抑制（`GameController.ets:1014`）。
这与 SPEC §2:61「自定义局不计入统计/排行榜（原版如此）」一致。

**唯一相关的缺陷不在统计，而在盘面**：自定义局被「新建/再玩一局」重开时，
盘面会被换成难度预设（见 P1）。

**问题三：有没有会让应用崩或卡死的输入？**

**0 处。** 输入层有三道闸（字符白名单、焦点范围、上限拒绝），
`clampSpec` 再夹一次，引擎层 `reset()` 还有最终兜底（`MinesweeperEngine.ets:195-198`）。
所有路径都收敛到有限整数，`cells` 数组最大 24×30=720，无越界、无死循环、无 NaN。
模态锁也没有吃掉按钮点击（`MinefieldCanvas.ets:157-170` 只放行 Down/Up 而不是直接 return）。
详见 §5。

### 1.4 键盘按键 → 字段变化

键盘共 11 个键（见 §6）：`1 2 3 / 4 5 6 / 7 8 9 / ⌫ 0`。

**数字键（`CustomField.inputChar`，`CustomField.ets:223-253`）：**

1. 字符必须是**单个** 0-9，否则返回 false（224-230）。
2. 焦点必须在 0..2，否则返回 false（232-234）。
3. **替换还是追加**：`(replaceNext || 焦点变了) ? 0 : 当前值`（236-237）。
   即「刚获得焦点时第一位数字覆盖旧值」，之后逐位追加 —— 与 Win7 输入框「获得焦点即全选」一致。
4. 追加后的值若**超过该框上限**，**拒绝这一位**（239-241）：值保持不变，返回 false。
   不是截断、不是回绕。
5. 若改的是高度或宽度，且当前雷数已超过新的 `maxMines`，**雷数被拉回上限**（244-249）。
   这一步是可见的（框里数字会变），但没有任何解释性提示。

**退格键（`CustomField.backspace`，`CustomField.ets:256-265`）：**
`Math.floor(cur/10)`。单位数退格后变成 **0**，不是空；再退格仍是 0。
退格后 `lastFocus` 置为当前焦点且 `replaceNext=false`，所以下一位数字是**追加**（例如 19 → 退格 → 1 → 输 5 → 15）。

## 2. 边界与非法输入逐条推演

面板层的两条硬规则决定了绝大多数推演结果：

- 超过上限 → 拒绝该次输入，值不变（`CustomField.ets:239-241`）。
- 确定时 `clampSpec` 统一夹取（`CustomField.ets:189-196`）：高度→[9,24]，宽度→[9,30]，雷数→[10, maxMines]，焦点→[0,2]。

### 2.1 高度（行）

| 输入 | 面板层实际发生了什么 | 确定后 | 是否有兜底 |
|---|---|---|---|
| 0 | 键盘输 `0`（首次=替换）→ 高度=0；或退格退到 0 | 9 | 有（`clampSpec` 190） |
| 8 | 输 `8` → 8 | 9 | 有 |
| 9 | 输 `9` → 9 | 9 | — |
| 24 | 输 `2` → 2；输 `4` → 24（24 ≤ 24，通过） | 24 | — |
| **25** | 输 `2` → 2；输 `5` → 25 > 24 **被拒** → 框里仍是 2 | **9** | 有，但结果是「下限」，既不是 24 也不是 25（P3） |
| 99999 | 输 `9` → 9；再输 `9` → 99 > 24 **被拒** → 之后每次都被拒 | 9 | 有 |

### 2.2 宽度（列）

| 输入 | 面板层实际发生了什么 | 确定后 | 是否有兜底 |
|---|---|---|---|
| 0 | → 0 | 9 | 有 |
| 8 | → 8 | 9 | 有 |
| 9 | → 9 | 9 | — |
| 30 | 输 `3` → 3；输 `0` → 30（30 ≤ 30，通过） | 30 | — |
| **31** | 输 `3` → 3；输 `1` → 31 > 30 **被拒** → 框里仍是 3 | **9** | 有，结果同样是下限（P3 同款） |
| 99999 | 停在 9 | 9 | 有 |

### 2.3 雷数

上限随盘面变化，先固定一个盘面再推演。下表「盘面」列以 9×9（上限 65）为例。

| 输入 | 面板层实际发生了什么 | 确定后 | 是否有兜底 |
|---|---|---|---|
| 0 | 输 `0` → 0 | 10 | 有（`clampSpec` 193，下限 10） |
| 1 | 输 `1` → 1（**框里会显示 1**，低于下限但输入层不拦下限） | 10 | 有 |
| 超过盘面格数 | 9×9 上限 65：输 `6` → 6；输 `6` → 66 > 65 **被拒** → 停在 6 | 10 | 有（面板层就拦住了，引擎层根本收不到） |
| 恰好上限 | 9×9 输 `6` `5` → 65 ✓；24×30 输 `6` `6` `8` → 668 ✓ | 原样 | — |
| **负数** | **不可达**。键盘没有负号键；`inputChar` 只收 0-9（224-230）；`backspace` 用 `Math.floor(cur/10)` 且 `cur ≥ 0`，恒不产生负数 | — | 不需要兜底 |
| 99999 | 24×30 上限 668：输 `9` `9` → 99；第三位 `9` → 999 > 668 被拒 → 停在 99 | 99 | 有 |
| 空 | 退格把单字符退成 0（不是空）；0 再退仍是 0 | 10 | 有 |

**「输入框为空」在当前实现下不存在**：字段最小值是 0，等价于「填了 0」，确定时被下限夹住。

### 2.4 三项都填 0 直接确定

`clampSpec` 依次得到 9 / 9 / 10 → 开出一局 **9×9、10 雷**（等价于初级）。
不会崩，但**没有任何提示**：用户以为开了一局 0×0 的怪盘，实际拿到的是初级盘。
原版 Win7 会弹一个「请输入有效的数字」错误框；这里静默替换（P3 同类）。

### 2.5 雷数上限到底是 668 全局还是按格数

| 盘面 | `min(668,(h-1)(w-1)+1)` | 说明 |
|---|---|---|
| 9×9 | 65 | |
| 9×30 | 233 | |
| 16×16 | 226 | |
| 16×30 | 436 | |
| 24×24 | 530 | |
| **24×30** | **668** | 只有最大盘才等于 668 |

- **面板层**：`CustomField.maxMines()`（202-207）按格数算，`maxOfField()`（512-523）用它做输入上限。
- **引擎层**：`MinesweeperEngine.maxMinesFor()`（184-188）同样按格数。
- **SPEC**：§2:56 写「10–668（**面板上限**）」，§2:59 说明「24×30 → 668，与面板上限吻合」；
  §8-2（379）的决定是「**面板层保留全局 668 的输入上限**，引擎层按尺寸夹取」。

**结论：代码与 SPEC §8-2 的决定不一致**（代码=按格数，SPEC=面板放行到 668）。
两个附带后果：

1. **输入顺序陷阱**：想填 668，必须先把盘面设成 24×30，否则雷数框连 66 都打不出来。
2. **缩小盘面会拉走雷数**：24×30×668 → 把高度改成 9 → 雷数被自动改成 233（`CustomField.ets:244-249`）。
   数字是看得见的，但没有解释。

## 3. 确定之后：标志与统计核实

### 3.1 `customGame` 标志的生命周期

| 时机 | 标志 | 盘面 | 是否正确 |
|---|---|---|---|
| 菜单 游戏→自定义（打开框） | 不变 | 不变 | 正确（取消后当前局继续） |
| 取消(C) / 红叉 | 不变 | 不变 | 正确 |
| **确定(O)** | `true`（`GameController.ets:1232`） | 换成自定义盘面 | 正确 |
| 菜单 初级/中级/高级 | `false`（150） | 换成预设盘面 | 正确 |
| 菜单 新建(F2) / 结束框「再玩一局」 | `false`（160） | **换成预设盘面** | **标志对了，盘面错了（P1）** |

`customGame` 只在三处被写：置位 1 处、清零 2 处，`startNewGame()` 本身不碰它（`GameController.ets:170-197`），
所以「打开自定义框 → 取消」不会误清标志 ✓。

### 3.2 统计写入点核实

- **唯一写点**：`GameStats.record()`（`GameStats.ets:67-89`）。它负责 `played += 1`、`won += 1`、
  连胜/连败累计、以及 `bestSeconds/bestDate` 写入。
- **唯一调用点**：`GameController.buildDialog()`（`GameController.ets:1008`），
  且被 `if (!this.customGame)` 包住（1007-1011）。
- `buildDialog` 只在终局时调用一次（`notifyGameOver` 的 `gameOverNotified` 闸 + 动画结束的
  `tickFrames` 分支），不会重复计数。
- `isNewBest` 同样被 `!this.customGame` 抑制（1014），所以自定义局不会污染最佳成绩。

**核实结论：自定义局没有被计入「已玩游戏 / 已胜游戏 / 百分比 / 连胜 / 最佳成绩」中的任何一项。符合规格。**

### 3.3 两个相关但次要的统计瑕疵

1. `GameStats.level = cfg.name`（`GameController.ets:1004`）在自定义局里也会执行，
   把这个静态字段写成预设难度名（如 `初级`）。全工程 grep 确认**没有任何地方读它**
   （只有 `GameStats.ets:138` 的声明和这一处赋值），所以是无害的死代码，但语义上是错的（P7）。
2. 自定义局结束时，结束对话框里显示的「最快时间」取的是 `bestTextOf(cfg.name)`（1012-1013），
   也就是**某个预设难度**的纪录。原版自定义局根本没有纪录可显示，这里显示的是无关的纪录（P6）。

## 4. 崩溃 / 卡死面检查

| 检查项 | 结论 |
|---|---|
| 输入字符白名单 | `inputChar` 拒绝非 0-9 与多字符（224-230），返回值不被使用也不会写坏状态 |
| 焦点越界 | `inputChar` / `backspace` 都先查 0..2（232-234、258-260） |
| 数值溢出 | 每次追加后比较上限，超了拒绝（239-241）；不可能出现天文数字 |
| 负数 | 不可达（键盘无负号、字符白名单、退格恒非负） |
| 空值 | 不可达（字段最小为 0） |
| 确定时的夹取 | `clampSpec` 三层夹取（190-194） |
| 引擎兜底 | `reset()` 里 rows→[1,24]、cols→[1,30]、mines→[1,maxMinesFor]（`MinesweeperEngine.ets:195-198`） |
| 内存 | `cells` 数组 = r×c ≤ 24×30 = 720 |
| 死循环 | `inputChar` / `backspace` 均为 O(1)；引擎布雷用部分 Fisher-Yates，有界 |
| NaN | 三处数值来源全是整数运算，无除法、无 `parseFloat` |
| 模态锁死 | `inputLocked`（`GameController.ets:109-110`）含 `customSpec !== null`；但 `MinefieldCanvas.handleTouch`（157-170）在锁住时**只放行 Down/Up 而不是直接 return**，所以按钮仍可点；`handleTap`（304-308）把点击转给 `customActionAt` ✓ |
| 焦点循环 | `focusField` 只接受三个固定 id（272-286），未知 id 直接忽略 |

**结论：没有任何输入路径会导致崩溃、死循环或界面无响应。**

## 5. 数字键盘细节

### 5.1 键位

`NumKeypad.ets:17-22` 定义了 **11 个键**（不是 12 个）：

```
1 2 3
4 5 6
7 8 9
⌫ 0  (空)
```

- 排布 3 列 × 4 行；第 4 行只有退格和 0，**右下角是空位**，点那里 `hit()` 返回空串 → 无动作。
- 键尺寸 34×30 参考像素，间距 4（`NumKeypad.ets:25-27`）；键盘整体 110×132。
- 键盘画在对话框右侧 12 参考像素之外（`GameController.ets:1202`），
  命中测试先判对话框再判键盘（1224-1250）→ **两者命中区不重叠** ✓。
- 退格键的字形是 U+232B（ERASE TO THE LEFT，`NumKeypad.ets:66`）。
  它**不是 emoji**，但系统 sans-serif 未必带这个码位，可能显示豆腐块（P8）。

### 5.2 退格在字段为空时

字段不可能为空（最小 0）。退格 0 → `Math.floor(0/10) = 0`，无变化、无副作用 ✓。

### 5.3 连续输入会不会溢出

不会。规则是「超上限就拒绝这一位」，不是截断也不是回绕：

- 高度框（上限 24）：`2` → 2；`5` → 25 被拒 → 停在 2。
- 雷数框（9×9，上限 65）：`6` → 6；`6` → 66 被拒 → 停在 6。

副作用是「拒掉的那一位没有任何反馈」，用户看到的是框里停着一个看似合法的数（P3）。

### 5.4 字段之间怎么切换

- **没有 Tab 键，也没有「下一个」键**。
- 切换方式只有一个：**点输入框**。
  `CustomField.hit()`（430-444）返回 `height` / `width` / `mines`，
  `customActionAt`（1242-1245）转给 `CustomField.focusField()`（272-286），
  它会切焦点并置 `replaceNext = true` → **下一次输入会替换该框的旧值**
  （Win7「获得焦点即全选」语义，正确）。
- 代价：输入框只有 60×21 参考像素，手机上是个小目标（P9）。

### 5.5 键盘的其余行为

- 键盘不响应硬件键盘/系统输入法（本就是画布自绘的触摸键盘）。
- 键盘上的键**不会**改变焦点，只改当前焦点字段的数字。
- 打开自定义框时焦点默认在「高度」（`CustomField.defaultSpec()` 的 `focus: 0`），
  因此第一下键盘数字直接改高度。

## 6. 问题清单（按严重度）

### P1 [HIGH] 自定义局的「新建 / 再玩一局」会把盘面换成难度预设

- **位置**：`GameController.ets:156-162`（`restart()`），调用点
  `Index.ets:36-37`（结束框「再玩一局(P)」）、`Index.ets:88`（菜单「新建」/F2）。
- **复现**：游戏 → 自定义 → 20 行 / 20 列 / 50 雷 → 确定 → 赢或输 →
  点结束框「再玩一局(P)」→ 盘面变成 **9×9**（初级预设），不是 20×20。
  菜单「新建(F2)」同样如此。
- **期望**：原版的「重新开始这个游戏(R)」/「再玩一局(P)」/F2 用**当前盘面参数**重开，
  自定义局应仍是 20×20×50（依据 SPEC §11:470 记录的 Win7 按钮语义「重新开始这个游戏」）。
- **实际**：`restart()` 用 `configOf(this.difficulty)` 的预设尺寸重开，并顺带把 `customGame` 清成 false。
- **影响**：玩家刚设好的自定义盘被静默替换；自定义局的「再玩一局」变成完全不同的另一盘。
  （统计口径没错 —— 新开的确实是预设局 —— 但盘面是错的。）
- **建议**：控制器里留住上一局的自定义尺寸（例如 `lastCustomRows/lastCustomCols/lastCustomMines`），
  `restart()` 在 `customGame` 为真时用它们，并**保持** `customGame = true`。

### P2 [MEDIUM] 面板层雷数上限与 SPEC §8-2 的决定不一致

- **位置**：`CustomField.ets:202-207`（`maxMines`）、`CustomField.ets:520`（`maxOfField` 用它）；
  规格侧 `docs/SPEC.md:379`（§8-2）、`docs/SPEC.md:56`（§2）。
- **复现**：9×9 盘面下打开自定义框，键盘输 `6` `6` → 第二位被拒（66 > 65），
  雷数框停在 6，无法填出 66。
- **期望（按 SPEC 的「怎么定」列）**：面板层放行到全局 668，引擎层按尺寸夹取。
- **实际**：面板层按 `(h-1)*(c-1)+1` 拦。
- **建议**：二选一并同步另一侧。
  倾向**保留代码行为**——它杜绝了「面板写 668、引擎悄悄降到 65」这种用户不可见的替换；
  代价只是必须先设盘面再设雷数。若改回 SPEC 的写法，则确定时需要明确提示「本盘最多 N 雷」。

### P3 [MEDIUM] 上限拒绝是静默的，且确定后落到下限而非上限

- **位置**：`CustomField.ets:239-241`（拒绝）、`CustomField.ets:190-193`（夹取）。
- **复现**：高度框输入 `2` `5` → 第二位被拒 → 框里显示 2 → 点确定 → 盘面是 **9 行**
  （既不是 24 也不是 25）。宽度框输 `3` `1` 同理得到 9 列。
- **期望**：要么当场提示「最大 24」，要么截断到 24，要么确定时给明确反馈。
- **实际**：用户输入被无声丢弃，最终拿到一个与自己意图无关的下限值。
- **建议**：被拒时给一次视觉/音效反馈；或把值截断到上限；在提示行里补上「当前框上限」。

### P4 [MEDIUM] 打开自定义框时按「当前难度预设」预填，不是按「当前盘面」预填

- **位置**：`GameController.ets:1170-1176`（`openCustomDialog` → `configOf(this.difficulty)`）。
- **复现**：玩一局 20×20×50 的自定义局 → 游戏 → 自定义 → 框里是 9/9/10。
- **期望**：原版用当前盘面尺寸预填。
- **实际**：用难度预设；自定义局的当前尺寸被忽略。若直接点确定，会静默切回初级盘。
- **建议**：预填改用 `engine.rowCount / colCount / mineCount`（自定义局时）或 P1 里建议的 `lastCustom*`。

### P5 [MEDIUM] 自定义框的缩放系数是陈旧的（借用了结束对话框的）

- **位置**：`GameController.ets:1179-1187`（`customLayout` 读 `this.dialogScale`）；
  `dialogScale` 只在 `dialogLayout()`（1030）里赋值，而 `dialogLayout()` 只在 `drawDialog()`
  且当前有结束框时才被调用。
- **复现**：刚进应用、还没玩完过一局（没弹过结束框）→ 游戏 → 自定义 →
  对话框按初值 1 画，明显偏小；折叠/展开换屏后也可能沿用换屏前的系数。
- **期望**：自定义框用自己按画布宽度算的系数。
- **实际**：首次是初值 1，换屏后是旧值。
- **说明**：命中测试与绘制用的是同一个系数，所以**点得准**，只是显示尺寸不对。

### P6 [MEDIUM] 自定义局时菜单仍给预设难度打勾，结束框也显示预设难度的最快时间

- **位置**：`GameController.ets:1294-1297`（菜单 `checked` 只看 `this.difficulty`）；
  `GameController.ets:1012-1013`（`bestTextOf(cfg.name)`）。
- **复现**：自定义 20×20 局进行中 → 菜单里「初级」仍然打着勾；赢一局 →
  结束框显示「初级」的最快时间与日期。
- **期望**：自定义局不应出现预设难度的勾选或纪录。
- **实际**：`difficulty` 永远是预设档（自定义局不改它）。
- **建议**：菜单加一个「自定义」勾选项、或自定义局时清掉三个预设的勾；
  自定义局的结束框隐藏「最快时间」两行。

### P7 [LOW] `GameStats.level` 被自定义局写成预设难度名，且该字段是死代码

- **位置**：`GameController.ets:1004`（唯一赋值点）、`GameStats.ets:138`（声明）。
- **说明**：全工程 grep 确认**没有任何读取点**。自定义局会把它写成 `初级` 等，
  但不影响任何行为。属于「意图不清但无害」。
- **建议**：删掉这行，或移进 `if (!this.customGame)` 分支。

### P8 [LOW] 退格键的 ⌫ 字形可能缺字形

- **位置**：`NumKeypad.ets:66`。
- **说明**：U+232B 不是 emoji，但系统 sans-serif 未必包含该码位，缺字形时会显示豆腐块。
- **建议**：真机看一眼；不稳妥就改成 `DEL` 文本。

### P9 [LOW] 键盘没有「下一个字段」键，换字段只能点输入框

- **位置**：`NumKeypad.ets:17-22`（无此键）、`GameController.ets:1242-1245`（点框切换）。
- **说明**：点输入框可以切换，功能完整；但输入框只有 60×21 参考像素，手机上目标偏小。
- **建议**：键盘加一个「下一个」键（切 focus 并重置 `replaceNext`），或把输入框做大。

### P10 [LOW] 提示行的「最大雷数」用的是夹紧后的行列，与框里的中间值可能对不上

- **位置**：`CustomField.ets:389-392` + `CustomField.ets:202-207`。
- **复现**：高度框正在输入 `1`（还没输完）→ 提示行已按 9 行算出「最大雷数 65」；
  若用户接着把高度输成 24，真正的上限应是 436。
- **建议**：提示行跟随未夹紧的值计算，或加一句「按当前盘面」。

### P11 [LOW] 自定义框确定分支多画一帧

- **位置**：`GameController.ets:1233-1234`：`startNewGame()` 内部已 `draw()`，之后又 `draw()` 一次。
- **影响**：无（多一次全画布重绘）。

### P12 [LOW] 结束框的「换个难度(D)」名不副实

- **位置**：`Index.ets:38-40`（`action === 'menu'` → 只 `closeDialog()`）。
- **说明**：SPEC §11:470 记录这个按钮原本是「重新开始这个游戏(R)」，手机版改成了「换个难度(D)」，
  但实现只关掉对话框，并没有换难度，玩家还得自己去菜单里点。
- **说明**：与自定义框相邻（自定义局结束后若点它，同样会落到 P1 的盘面问题），一并记录。

### P13 [INFO] 已核实无问题的点（供回归参考）

- 自定义局不进统计（`GameController.ets:1007-1011`），符合 SPEC §2:61。
- `customGame` 只在确定分支置位，`setDifficulty`/`restart` 清零，语义闭合。
- 模态锁不会吃掉点击（`MinefieldCanvas.ets:157-170` 放行 Down/Up）。
- 键盘与对话框命中区不重叠（12 参考像素间隔）。
- 引擎层对 rows/cols/mines 三重夹取兜底（`MinesweeperEngine.ets:195-198`）。
- 负数、空值、越界焦点均不可达。
- 面板层区间常量与引擎 `CUSTOM_*` 逐项一致（但目前是两处独立定义）。

### 8.2 28 条用例覆盖了什么

| 组 | 条数 | 覆盖内容 | 断言 |
|---|---|---|---|
| 菜单路径 | 1 | 游戏 → 自定义 → 框打开 | 三个值区都 changed |
| 数字键 | 11 | `1`–`9` 与 `0` 各一条（高度框聚焦后按）+ 一条「按 9 值不变」的边界 | 高度值区 changed / changed（同值那条） |

| 空格子 | 1 | 键盘右下角没有键的格子（col2,row3） | 三个值区全 unchanged（点了什么也不发生） |
| 焦点切换 | 4 | 点宽度框 / 点雷数框 / 从雷数框切回高度框 / 切走再切回（验证「获得焦点即全选」） | 目标框 changed，其余 unchanged |
| 越界拒绝 | 3 | 高度 2→**5 被拒**、宽度 3→**1 被拒**、雷数 66→**9 被拒**（669 > 668） | 拒绝后值区 **unchanged** |
| 确定 | 2 | 24 行 30 列真开一局；高度输 0 后确定（下限在确定时夹到 9） | `layout_regex`：`格边=72px 棋盘原点=(-440,408)` / `格边=108px 棋盘原点=(154,754)` |

| 预填回归 | 1 | 开一局 24×30 → 再打开框 → 什么都不改直接确定 → 盘面应仍是 24×30（P4） | 两次 `layout_regex` 都是 24×30 基线 |

**布局基线取自 `tools/check_layout.py` 的 `V3_BASELINE['Mate 90 Pro 模拟器']`**：
初级 = `(3, 108, 154, 754)`、自定义 24×30 = `(2, 72, -440, 408)`；
布局日志格式见 `GameController.ets:308-311`。

### 8.3 已知依赖（跑测器已定稿，这里只留结果）

1. **基准语义 = 动作基准**（跑测器现状）：`changed`/`unchanged` 拿「上一个动作之前」的画面比。
   本表所有用例已按这个语义离线复核通过（§8.4）。
2. **值区断言对「显示 0」只能验到「变了」**：`0` 与 `9` 的墨迹覆盖率不同，但没有 OCR，
   所以「输入阶段不夹下限」「切回焦点是替换不是追加」这两条只能靠 `shot` 人工看图核对
   （用例 desc 里已写明）。
3. **`key: "ok"/"cancel"` 映射到框内按钮**（跑测器现状，与本表一致）：确定 = `custom` 空间
   `(151,170)`、取消 = `(229,170)`；键盘的 11 个键里本来就没有确定/取消。
4. **`keypad` 空间原点** = 键盘自身左上角，换算到画布 = `customOx + (280+12)*s + x*s`（跑测器现状，与本表一致）。

### 8.4 按「动作基准」语义改过的 3 条（2026-11-01 09:45）

离线复核方式：把 `CustomField` 的状态机（focus / replaceNext / inputChar / backspace / clampSpec）
与 `GameController` 的版式公式翻成 Python，逐条回放 28 条用例，检查每条断言在其基准下是否成立。

| 用例 | 问题 | 改法 |
|---|---|---|
| `custom.key.digit9` | 高度框预填就是 9，按 9 之后值没变 → 像素也没变，`changed` 必挂 | 先按 `1` 再按 `9`（框里变 19），再断言 changed；另加一条 `custom.key.digit9.same_value` 专门断言「同值时像素不变」 |
| `custom.prefill.current_board` | 原来的写法是「重开框后高度/宽度值区 unchanged」，但按动作基准，重开框那一帧的基准是**棋盘画面**，跟对话框画面比必然判成「变了」 | 改成**日志断言**：重开框后什么都不改直接确定，布局应仍是 24×30（若预填错退回 9/9，确定后就是 `格边=108px`）；另留一张 `custom_prefill_reopened` 证据图供人工看预填值 |

结果：**28 条用例离线复核 0 失败**，11 个键盘键全覆盖，每个 tap 的落点与每个值区的位置也用脚本按源码常量复算过（0 问题）。
